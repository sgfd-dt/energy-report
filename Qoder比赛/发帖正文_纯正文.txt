队伍名称：能动第一人（单人参赛）

一、自我介绍

我是能源与动力工程专业的大一学生，2026 年 10 月才开始接触编程和 AI。

一开始的原因很直白：觉得「让电脑替你把活干完」这件事很牛，想着以后上班能轻松点。后来越学越觉得不对劲 —— AI 这两年进得太快，几年后很可能就把我原本想干的活抢了。所以学它的理由慢慢从「偷懒」变成了「别被甩下」。

现在的水平：能写几十行 Python，读 csv、按设备加总、出报告这几步是我自己写、自己逐行对过账的（合计 2056.30，和网页版一模一样）。网页部分基本是 Qoder 写的，我不会前端。

这也正是这个作品想验证的事：一个不懂前端的大一学生，能不能靠 AI 把一个完整的东西从零做到上线，让评委点开就能用。

对我来说它最大的意义就一句：这是我第一次做出一个别人能打开的东西。


二、你的作品是什么，谁在什么场景下用

一句话：给宿舍长、实验室管理员、车间电工用 —— 把电表导出的 CSV 拖进去，30 秒看出哪台设备最费电、有没有可疑读数、该先查谁。

打开就是 20 行示例数据，不用先准备文件。顶部还有四个示例标签（正常示例 / 有坏行 / 缺一列 / 有异常读数），点一下就能把下面的能力当场演示一遍。

给它自己的数据之后，它给六样东西：

1. 三个关键数字：合计电量 2056.30 kWh、估算电费 1233.78 元、估算碳排 1.19 吨（电价和碳排系数可以自己改）。
2. 按设备占比排行：锅炉C 电量 1028.00 kWh、占比 50.0%，带横条，第一名叫「最费电」。
3. 一句人话结论：锅炉C 占了 50.0%（1028.00 kWh），是最大用电设备。建议先查它的运行时长，看有没有空转。
4. 可疑行标红：某台设备某天用电超过它日均的 2 倍，那一行标红并写「异常 · 是日均的 2.6 倍」；只要出现异常行，表格会自动展开，不用自己去翻那 20 行。
5. 原始数据表格：每台设备每天的电量；坏行打感叹号、跳过，并在顶部写清「跳过 N 行」。
6. 能带走的东西：一键下载 能耗报告.txt；数据表头不对时，页面顶部直接说缺哪一列，并给一份 能耗模板.csv 可以下载。

谁会用：
· 小工厂、车间的电工：每月抄完表，想知道这个月哪台设备最费电；
· 学校、宿舍后勤：想知道电费为什么突然变高；
· 我自己：家里有电表读数，想算哪台电器最耗电。

三种人打开它的时机是同一个：手上有一张 CSV，但不想用计算器。


三、为什么做（问题或想法的来源）

三件事凑到一起：

1. 专业：我学能源与动力工程，以后要和锅炉、空压机、冷却塔这些设备打交道，「一台设备一个月吃了多少电」是我迟早要算的东西。
2. 目标：我想成为 Agent 工程师，而 Agent 的本事是「接住一句人话，做完一件事」。能耗记录器就是最小的这件事：给数据，出结论。
3. 现实：真实电表导出的数据不干净。我自己造的三份测试数据里就有：空电量、手写成「二百一十」、少一列的残缺行。手工算或用 Excel，遇到这些要么崩，要么悄悄算错 —— 所以这个工具必须能「标出来 + 跳过 + 说清跳了几行」，还得能发现不正常的读数（这也是后来加「可疑行标红」的原因）。

四、怎么用（5 步以内）

1. 打开链接，先看默认的示例数据（电脑、手机都能开）。
2. 点左上「选择 CSV 文件」，选你自己的电表数据，表头是：日期、设备、电量kWh、运行小时。
3. 看首屏三个数字：合计电量、估算电费、估算碳排。
4. 往下看「按设备」排行和最后那句结论；有异常行会在表格里标红（此时表格自动展开，直接能看到是哪一行）。点某台设备，还能只看这一台。
5. 要存档就点「下载报告」，得到一份 能耗报告.txt。

表头不对不会白屏：顶部会写「这个文件缺少「电量」列。需要的表头是：日期,设备,电量kWh,运行小时」，旁边有「下载 CSV 模板」。

五、用 Qoder 做出来的过程（哪几步交给它、我改了什么）

一句话：我出题、我验收，Qoder 写代码、建站、发布。两天里从「一个按钮弹你好」做到「传一份 CSV，出数字、出结论、还能发现异常」。下面按我实际做的顺序写。


（1）动手之前，我先自己看一遍

我给它提要求之前，会先做三件事。

第一，先看它上一次写的代码。我不全看，只看三处：字段名有没有被改、那个「2 倍」的阈值是不是写死在代码里、界面有没有另起一套画法。做异常检测那一步，我先确认它是「只在表格里标出来」，不是「把行删掉」。因为删了行合计就变了，我后面所有数字都得重算。

第二，先自己把结果算出来。异常的规则是「超过这台设备日均的 2 倍」，那我就先算一遍：四台设备的日均是 205.6、127.7、44.4、33.5 度，示例数据里偏离最大的一行也只有 1.18 倍，所以打开页面必须显示「未发现异常」。它要是显示有异常，我马上就知道错了。点设备过滤那次也一样，638.60 ÷ 5 = 127.72，我先算好这个数，再去页面上看是不是它。

第三，先把要求写下来，再让它动手。界面要「干净」，我不会说「你帮我弄好看点」，而是把要求写死：底色 #F6F7F9、卡片白底、不要阴影、橙色只给按钮和第一名、字号只有 28/40/16/14/12 五档、内容宽度 960。写成文档之后，一次只贴一段给它。

找 bug 也是这个顺序：先复现，再说。表格错位那次，我先用无头浏览器把窗口拖到 700px 宽截了一张图——行底的横线只画到一半，异常标签已经跑到表格外面（图8）。我把图发给它，说清是哪一行的问题，一次就改对了。

【图8：700px 宽下，异常标签被做成了第 5 个表格单元格，行线只画到一半、标签浮在表格外】


（2）能长期用，靠的是一点点补

第一版只能算一个合计。后面这些东西是一点点加上去的，每一条我都知道为什么要加：

1. 脏数据。电表导出来的数据一定不干净：有空电量、有手写成「二百一十」的、有少一列的。所以缺的标出来、坏的跳过，还要在页面上说清跳了几行。
2. 单位。全用 kWh，电价按 元/kWh、碳排按 kg/kWh，导出的报告里也是 kWh。一开始混着「度」和 kWh，我自己看着都别扭。
3. 能带走。加一个「下载报告」，拿到 txt 就能发给别人。表头不对的时候，直接说缺哪一列，再给一份 CSV 模板可以下载。
4. 不用先准备文件。打开就有 20 行示例数据，顶上四个标签一点就能看四种情况：正常、有坏行、缺一列、有异常读数。
5. 从「算出来」到「看出来」。某台设备某一天用的电超过它日均的 2 倍，就把这一行标红，写清是几倍。
6. 能钻下去。点某台设备，表格只看这一台，再多一行「日均多少、最高是哪天」。
7. 结论能查。点「为什么这么判断？」，把结论拆成三行算式，全都是按当前数据现算的。



【图9：结论旁边点「为什么这么判断？」——三行算式全是按当前数据现算的】


（3）难看和不好用的地方

1. 第一版界面太杂：一屏 20 行表格，深色底 + 橙按钮 + 橙横条 + 斑马纹 + 描边 + 阴影，六层东西一起挤。我先把「为什么显杂」列成 6 条，再分三次让它改：先排版（标题 → 三个数字 → 排行 → 结论 → 表格收起来），再改手机（两列），最后把排行改成紧凑列表。
2. 电脑上三个大数字挤在一起（图10）：40px 的数字、三列等宽，一列放不下「2056.30 kWh」，就直接压到隔壁那一列上。把单位拆到下面一行、列宽改成自适应，才解决。
3. 提示「检测到 1 行异常」，但异常行在第 11 行、表格是收起来的。评委听得到结论、看不到证据。改成有异常就自动展开。
4. 手机上原来要左右滑动，现在两列，滑都不用滑。

【图10：修之前，三个大数字挤在一起（无头浏览器 1000px 宽下复现）】


（4）测试和上线

每改完一次我都跑一遍，四组数字一个都不能变：

1. 四份 CSV 对账：正常 2056.30 / 跳过 0；1 行坏 474.10 / 跳过 1；3 行坏 263.60 / 跳过 3；缺列那份，三个数字显示「—」并给出提示条。
2. 用脚本验收：写个小脚本把 CSV 直接塞进上传框，再把页面上的数字读出来对比。不靠眼睛看，靠数字对不对。
3. 三个宽度各截一次图：960、760、375；手机再用 375 宽的 iframe 单独验一遍。
4. 交互回归：四个示例标签各点一遍，点设备、点「为什么这么判断」、再点一次收起，全跑一遍。
5. 同一个需求我先用 Python 手写过一遍（60 多行，输出 报告.txt），所以网页里每个数字我都能对上——不是「看着像对的」，是 2056.30 对上 2056.30。

这里记一个我自己的错：我在要求里写「有坏行的数据跳过 1 行」，其实那份数据坏了两行。是脚本跑出来的数字对不上才发现的。写在这里，是因为验收的意义就是让这种错被发现。

部署也是用它做的：在 Qoder 的「站点」入口写一条需求（图11），它自己读技能、生成文件并发布（图12）。第一次发布后「可见范围」默认是「仅自己可访问」（图13），外网打开 404，改成「任何人都可访问」才通（图14）。最后用手机流量和无痕窗口各打开一次，确认不是缓存骗自己。

六、还没做完的（诚实写明）

1. 那句结论现在是规则写的（最大设备 + 模板句 + 异常倍数），还没接大模型。下一步是接后端让它「看懂数据自己说话」—— 现在这个站是纯前端静态站，网页里直接调大模型 API 会把 Key 暴露在 JS 里，所以没做。
2. 数据不保存：刷新就回到示例数据，没有账号、没有数据库。
3. 异常判定的阈值固定是「日均的 2 倍」，对用电量波动特别大的设备不一定合适。
4. 表格现在只有 4 列（日期 / 设备 / 电量 / 运行小时），还没支持不同表头的自定义映射。

如果评委只有 30 秒，最值得点的三个地方：
① 点顶部的「有异常读数」—— 看它怎么把可疑读数抓出来；
② 点结论下面的「为什么这么判断？」—— 看结论不是黑箱；
③ 点「锅炉C」—— 看它怎么把一台设备单独拎出来看。



七、感想和总结

一句话说清它现在能干什么：把电表导出的 CSV 拖进去，30 秒知道总电量、哪台设备最费电、有没有可疑读数，而且每一条结论都能点开看它是怎么算出来的。

原本我以为这件事两天能很快做完，结果大部分时间不是花在「让它写」，而是花在「确认它写对没有」。有些需求它一次就过，有些要来回三次。我慢慢发现，真正难的不是提需求，是判断结果对不对——这个本事只能靠自己先把数字算一遍。

有一件事我印象最深：它说改好了，我按了刷新，线上还是旧版。后来才知道它那个发布插件掉线了，发布这一步根本没跑成。从那次以后我不看它怎么说，只看线上文件有没有真的变。

还有一句是关于 AI 的。我一开始学它，是觉得它牛、想偷懒；后来是怕几年后它把我本来想干的活抢了。这两天做完这个东西，那种怕少了一点：它替我干的是我最不擅长的那部分，但它不会替我想清楚要什么，也不会告诉我哪个数字错了。判断力是我自己的，做一次长一点。

我也还差得远：不会前端，Python 只到几十行。但这不耽误我做出一个别人能打开、能用、能核对的东西。这是我第一次有这样一个东西，比学会哪一个语法重要得多。

接下来想做的两件事：把结论接上真正的后端大模型（现在是规则写的），再找一份真实的电表数据跑一遍。链接会一直开着，欢迎拿你自己的电表数据试。
