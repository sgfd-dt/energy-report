## 二、干净的三条底层规则（判断标准，不是审美偏好）

1. **一屏一件事**：手机首屏只回答一个问题——「最费电的是谁」。表格、参数都不是这一屏的事。
2. **一个主色**：橙色只用于「可以点的东西」和「第一名」。其余全部用灰阶（#111827 / #6B7280 / #E5E7EB）。
3. **层级靠字号，不靠装饰**：同一个信息不要同时用「底色 + 描边 + 阴影 + 颜色」四种手段强调，最多两种。

## 四、粘给 Qoder 的三段话（一段一次，验收完再下一段）

> 铁律：**一次只贴一段**。三段一起贴，它会把整个文件重写一遍，容易把数据逻辑改坏。

### 第 1 段：版式骨架（只改布局和视觉，不改逻辑）

```
只改布局和视觉，不要改数据解析、汇总、占比、诊断的任何逻辑和文案。

1) 页面最上方加标题区和副标题：主标题「能耗记录器」，副标题「上传电表 CSV，30 秒看出哪台设备最费电」。
2) 首屏从上到下的顺序改成：
   标题区 → 主按钮「选择 CSV 文件」→ 一行小字（示例数据说明 + 跳过 N 行）
   → 三个关键数字（合计电量 / 估算电费 / 估算碳排，大字号、等宽数字）
   → 按设备排行 → 原始数据表格（默认折叠，只显示前 5 行，右上角「展开全部」）
3) 配色改成浅色：页面底 #F6F7F9，卡片底 #FFFFFF，正文 #111827，次要文字 #6B7280，
   分割线 #E5E7EB。橙色 #FF6B35 只用在主按钮和排行第一名的横条上，其他地方不要橙色。
4) 字号：页面标题 28px，三个关键数字 40px，分区标题 16px，正文 14px，辅助文字 12px，行高 1.6。
5) 间距：卡片内边距 20px，块与块之间 24px，页面左右内边距手机 16px / 桌面 24px，
   内容最大宽度 720px 居中。圆角：卡片 12px，按钮全圆角。
6) 删掉：表格斑马纹、卡片上的阴影（只保留 1px #E5E7EB 描边）、表格顶部那条橙色横线。
7) 页面最底部留 48px 空白（右下角有平台徽标会盖住内容）。
8) 把浏览器标签页标题（index.html 里的 `<title>`）从「CSV 表格预览」改成
   「能耗记录器 · 上传电表 CSV，看哪台设备最费电」。评委截图时会连标签页一起截到。
9) 手机端（宽度 ≤ 640px）把「选择 CSV 文件」按钮固定在页面顶部，往下滚时始终能点，
   不用滚回最上面才能换文件。
```

### 第 2 段：表格与参数

```
继续只改视觉，不改数据逻辑。

1) 手机端（宽度 ≤ 640px）表格改成两列：设备 / 电量(kWh)；日期用 12px 灰字放在设备名下面，
   不要横向滚动，所有列都要装得下。
2) 电价和碳排两个输入框收进一个「参数设置」折叠区，默认收起；
   收起的标题行用 12px 灰字显示当前值：`电价 0.6 元/度 · 碳排 0.58 kg/度`。
3) 单位全站统一成 kWh：表头「电量(kWh)」，合计行「合计 2056.30 kWh」，删掉「度」的写法，
   保留「元」「kg」这些电费碳排单位。
```

### 第 3 段：排行列表

```
继续只改视觉。把「按设备」的四张大卡片改成一张白卡片里的紧凑列表：

1) 每行结构：左边设备名（16px 加粗）+ 电量（14px 灰色）；右边占比（16px，等宽数字）。
2) 每行下面是 8px 高的横条：底 #E5E7EB；第一名填充 #FF6B35，其余填充 #111827 的 20% 透明度。
3) 行与行之间 12px，行与行之间不要描边，只在最外面套一张白卡片（12px 圆角、1px #E5E7EB）。
4) 第一名那行的设备名后面加一个小标签「最费电」，12px 橙字 + 浅橙底，不要发光不要动效。
```

## 四之二、第 1 段验收结果（2026-11-18）

已拉线上代码核对（公开链接 200，`index.html` 59805B / `app.js` 13108B / `styles.css` 9363B，上一版为 58132 / 12480 / 9117，**确认真的重新发布了**）。

9 条落地 8 条：title、h1+副标题、首屏顺序、表格默认折叠只留 5 行、浅色配色变量、橙色只留主按钮与第一名、字号链、最大宽 720、手机按钮吸顶。

**唯一没做到**：总览里的三个数字是「合计电量 / 设备数 / 原始行数」，不是「合计电量 / 估算电费 / 估算碳排」——电费碳排还挤在下面那行小字里。对 Hack4Good 赛道来说，环保价值必须放在首屏，所以补这一句：

```
总览区的三个数字现在依次是「合计电量 / 设备数 / 原始行数」。把后两个换成
「估算电费」和「估算碳排」：电费 = 合计电量 × 电价参数，显示成「1233.78 元」；
碳排 = 合计电量 × 碳排参数 ÷ 1000，显示成「1.19 吨」。
设备数和原始行数缩小成一行 12px 灰字，放在这排数字下面：「4 台设备 · 20 行原始数据」。
原来那行「≈ 1233.78 元电费 · ≈ 1.19 吨二氧化碳」删掉（数字已经放大到上面），
两个输入框保留原行为，暂时不要折叠。
```

数字没被改坏（我自己求和验过）：合计 2056.30、电费 1233.78、碳排 1.19 吨。

**补丁已验收通过（15:0x 二次拉取）**：三个数字变成 合计电量 / 估算电费 / 估算碳排，下面一行「4 台设备 · 20 行原始数据」，原来的 ≈ 元电费 · 吨二氧化碳 那行删掉了，输入框改数值仍会实时刷新这两个数字。**第 1 段 100% 完成。**

## 四之三、界面定稿后发现的真实 bug（2026-11-18 15:20 手机/电脑截图）

界面三段全过之后，用户发的电脑截图暴露出**三个数字在电脑上重叠**：「2056.30 kWh」「1233.78 元」「1.19 吨」互相盖住。手机正常（≤640px 变单列）。

原因（读线上 `styles.css` 确认）：`.stats { grid-template-columns: repeat(3, minmax(0,1fr)) }` + `.stat__value { font-size: 40px; white-space: nowrap }`。内容最大宽 720、三列各约 213px，而「2056.30 kWh」在 40px 下约 230px，nowrap 让它画到隔壁列上。只有 ≤640px 才切单列，所以 641–1000px 这段窗口全都会叠。

**教训**：拉代码只能核对结构和数值，**布局重叠必须肉眼在真实窗口里拖一遍**。

修法 prompt：

```
电脑上总览区三个数字重叠了：「2056.30 kWh」「1233.78 元」「1.19 吨」互相盖住。
只改样式，不要改任何数字逻辑：

1) 把单位从大数字里拆出来：index.html 每个 .stat__value 里放两个子 span——
   <span class="stat__num">2056.30</span><span class="stat__unit">kWh</span>；
   app.js 只往 .stat__num 写数值，单位写进 .stat__unit。
2) .stat__num 用 40px / 700 / tabular-nums；.stat__unit 用 16px、普通字重、颜色 #6B7280，
   与数字基线对齐，左边留 6px。
3) .stats 改成 grid-template-columns: repeat(auto-fit, minmax(190px, 1fr))，
   窗口变窄时自动从三列变两列、一列。
4) 窗口宽度 900px 以下时 .stat__num 字号降到 32px。

验收：把浏览器窗口从 1400px 慢慢拖到 375px，三个数字全程不重叠、不被截断；手机上仍是一行一个。
```

## 四之四、大屏太窄（2026-11-18 15:42）

现象：1920 宽屏幕下内容只占中间一条窄柱，四周大片空白，4 列表格挤在中间。

原因：**我规范里写的 `max-width: 720px` 太窄**，不是 Qoder 改坏。720 适合纯文字阅读，但这里主体是 4 列表格 + 三列数字，桌面应该给 960。

```
页面在电脑大屏上太窄：内容最大宽度 720px，1920 宽的屏幕上只占中间一小条。
只改样式，不改逻辑：

1) 内容最大宽度从 720px 改成 960px，仍然水平居中。
2) 宽度 ≥ 960px 时页面左右内边距 32px；字号沿用现有值，不要重排。
3) 原始数据表格跟随内容宽度铺开，不要在中间挤成一团。
4) 手机（≤640px）保持现在 100% 宽 + 16px 内边距，一个像素都别动。

验收：1920 宽屏上内容约占屏一半、不显空；1366 笔记本上不出现横向滚动；手机和现在完全一样。
```
