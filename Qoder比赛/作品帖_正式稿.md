> 说明：事实来自 `过程记录.md` 与实测；语气按大一学生的口吻写，不要改成"商业计划书"。
> 发布位置：天池大赛官网 → 本赛题页 → 论坛发帖。必须包含官方要求的五个部分（下面的一～五对应）。

## 一、自我介绍

我是能源与动力工程专业的大一学生，2026 年 10 月才开始接触编程和 AI，目前的目标是成为 Agent 工程师。学 Agent 最好的方式是拿自己的专业出题，所以我选了「能耗」这个我最熟的场景 —— 它每天都会产生数据，而算数据恰好是最烦人的活。

## 二、你的作品是什么（一句话说清谁在什么场景下用）

**一句话**：给宿舍长、实验室管理员、车间电工用 —— 把电表导出的 CSV 拖进去，30 秒看出哪台设备最费电、有没有可疑读数、该先查谁。

打开就是 20 行示例数据，不用先找文件。**顶部有四个示例标签**（正常示例 / 有坏行 / 缺一列 / 有异常读数），点一下就能把下面四件事都演示一遍，不用自己准备文件。给自己的数据后，它给六样东西：

1. **三个关键数字**：`合计电量 2056.30 kWh` / `估算电费 1233.78 元` / `估算碳排 1.19 吨`
2. **按设备占比排行**：`锅炉C 电量 1028.00 kWh 占比 50.0%`，带横条，第一名叫「最费电」
3. **一句人话结论**：`锅炉C 占了 50.0%（1028.00 kWh），是最大用电设备。建议先查它的运行时长，看有没有空转。`
4. **可疑行标红**：某台设备某天用电超过它日均的 2 倍，那一行标红并写「异常 · 是日均的 2.6 倍」；而且**只要有异常行，表格会自动展开**，不用自己去翻那 20 行
5. **原始数据表格**：每台设备每天的电量，坏行打感叹号、跳过并在顶部写「跳过 N 行」
6. **能带走的东西**：一键下载 `能耗报告.txt`；数据表头不对时，页面顶部直接告诉你「缺哪一列」，并给一个 `能耗模板.csv` 可以下载

**谁会用**：小工厂 / 车间的电工（每月抄完表想知道哪台最费电）、学校与宿舍后勤（电费突然变高想找原因）、我自己（家里电表读数想算哪台电器最耗电）。三种人打开它的时机是同一个：**手上有一张 CSV，但不想用计算器**。

## 三、为什么做（问题或想法的来源）

三件事凑到一起：

1. **专业**：我学能源与动力工程，以后要和锅炉、空压机、冷却塔这些设备打交道，「一台设备一个月吃了多少电」是我迟早要算的东西。
2. **目标**：我想成为 Agent 工程师，而 Agent 的本事是「接住一句人话，做完一件事」。能耗记录器就是最小的这件事：给数据，出结论。
3. **现实**：真实电表导出的数据**不干净**。我自己造的三份测试数据里就有：空电量、手写成「二百一十」、少一列的残缺行。手工算或 Excel 遇到这些，要么崩，要么悄悄算错 —— 所以这个工具必须能「标出来 + 跳过 + 说清跳了几行」，还要能**发现不正常的读数**（这也是后来加「可疑行标红」的原因）。

## 四、怎么用（5 步以内）

1. 打开链接，先看默认的示例数据（电脑、手机都能开）
2. 点左上「选择 CSV 文件」，选你自己的电表数据（表头是：日期,设备,电量kWh,运行小时）
3. 看首屏三个数字：合计电量、估算电费、估算碳排
4. 往下看「按设备」排行和最后那句结论；有异常行会在表格里标红（此时表格自动展开，直接能看到是哪一行）
5. 要存档就点「下载报告」（`能耗报告.txt`）

> 表头不对不会白屏：顶部会写「这个文件缺少「电量」列。需要的表头是：日期,设备,电量kWh,运行小时」，旁边有 `下载 CSV 模板`。

### 我的验收方式（这部分比功能更能说明问题）

我不是看聊天窗口里它说「改好了」就点通过，而是：

1. **把线上文件拉下来**（`Invoke-WebRequest` 抓 `index.html` / `app.js` / `styles.css`），用文件大小变化判断「它到底发布了没有」。真发生过一次：它说改好了，线上还是旧版（Sites 插件掉线，publish 没跑起来）。
2. **看它写的代码**：异常检测的阈值是不是常量、标签是不是新开了一个表格列、扣掉坏行后合计对不对。
3. **自己造数据打进去**：写一段脚本把四份 CSV（正常 / 1 行坏 / 3 行坏 / 缺列）喂进「选择 CSV 文件」，再把页面上的数字读出来对账 —— `2056.30`、`474.10`、`263.60`，一个数都不能变。
4. **用无头浏览器在多宽度截图**：960 / 760 / 375。这一招抓到了两个真 bug：一是三个大数字在 641–1000px 之间会互相重叠；二是异常标签被它做成了第 5 个表格单元格，窗口一窄整张表错位、行线只画到一半。两个都是我拿截图摆到它面前才改对的。

**最关键的一步不在网页里**：同一个需求，我先用 Python 手写过一遍（`m2_汇总.py`，60 多行，输出 `报告.txt`）。所以网页版的每个数字我都能**逐位对账** —— 不是「看起来对」，是 `2056.30` 和 `2056.30` 对上。

## 六、还没做完的（诚实写明）

- 那句结论现在是**规则写的**（最大设备 + 模板句 + 异常倍数），还没接大模型。下一步是接后端让它「看懂数据自己说话」——现在这个站是纯前端静态站，网页里直接调大模型 API 会把 Key 暴露在 JS 里，所以没做。
- 数据**不保存**：刷新就回到示例数据，没有账号、没有数据库。
- 异常判定的阈值固定是「日均的 2 倍」，对用电量波动特别大的设备不一定合适。
- 表格现在只有 4 列（日期/设备/电量/运行小时），还没支持不同表头的自定义映射。
