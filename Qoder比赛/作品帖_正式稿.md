# 作品帖（正式稿 · 2026-11-17 草稿）

> 说明：这是草稿，事实来自 `过程记录.md` 与实测；语气按大一学生的口吻写，不要改成"商业计划书"。

## 一、自我介绍

我是能源与动力工程专业的大一学生，2026 年 10 月才开始接触编程和 AI，目前的目标是成为 Agent 工程师。学 Agent 最好的方式是拿自己的专业出题，所以我选了「能耗」这个我最熟的场景 —— 它每天都会产生数据，而算数据恰好是最烦人的活。

## 二、这是什么，谁在什么场景用

**是什么**：能耗记录器是一个网页。把电表导出的 CSV 拖进去，几秒钟内给出四样东西：

1. 每台设备每天的电量表格（原始数据，看得见）
2. 总电量（`合计 2056.30 度`）
3. 按设备占比的排行（`锅炉C 1028.00 度 占比 50.0%`，带横条）
4. 一句人话结论（`锅炉C 占了 50.0%，是最大用电设备。建议先查它的运行时长，看有没有空转。`）

**谁会用**：

- 小工厂 / 车间的电工：每月抄完表，想知道这个月哪台设备最费电
- 学校 / 宿舍后勤：想知道电费为什么突然变高
- 我自己：家里有电表读数，想算哪台电器最耗电

三种人打开它的时机是同一个：**手上有一张 CSV，但不想用计算器**。

## 三、为什么做

三件事凑到一起：

1. **专业**：我学能源与动力工程，以后要和锅炉、空压机、冷却塔这些设备打交道，"一台设备一个月吃了多少电"是我迟早要算的东西。
2. **目标**：我想成为 Agent 工程师，而 Agent 的本事是"接住一句人话，做完一件事"。能耗记录器就是最小的这件事：给数据，出结论。
3. **现实**：真实电表导出的数据**不干净**。我自己造的三份测试数据里就有：空电量、手写成"二百一十"、少一列的残缺行。手工算或 Excel，遇到这些要么崩，要么悄悄算错 —— 所以这个工具必须能"标出来 + 跳过 + 说清跳了几行"。

## 四、怎么用（4 步）

1. 打开链接（默认已加载 20 行示例数据，不用先找文件）
2. 点左上「选择 CSV 文件」，选你自己的电表数据
3. 看表格和 `合计 X.XX 度`
4. 往下看占比排行和最后那句诊断

## 五、用 Qoder 的过程（截图见 `截图\`）

一句话概括：**我出题、验收，Qoder 写代码**。一天之内从"一个按钮弹「你好」"做到"数据 → 数字 → 结论"。

| 我提的需求 | 它做了什么 | 我怎么验收 | 截图 |
|---|---|---|---|
| 一个单页，按钮点一下弹「你好」 | 生成 `index.html`/`app.js`/`styles.css` 并发布 | 外网打开，按钮能弹 | 01–04 |
| 顶部加「选择 CSV 文件」，选完显示成表格 | 自写 CSV 解析（引号、BOM、GBK 回退） | 塞 20 行数据 → 21 行 × 4 列表格 | 05 |
| 缺数据标感叹号、错误数据跳过 | `is-bad` 类 + 浅红底 + `跳过 N 行` | 三份数据对账 0 / 1 / 3 | 07 |
| 表格下面加合计 | 只累加有效行 | `2056.30` / `474.10` / `263.60` | 08 |
| 按设备分组 | 四行，按电量排序 | 与 Python 版 `报告.txt` 逐位一致 | 09 |
| 改成卡片 + 占比 + 横条 | 四张卡片 | `50.0 / 31.1 / 10.8 / 8.2` | 10 |
| 没有文件时显示示例数据 | 内置 20 行示例 | 打开即有内容 | 10 |
| 加一句诊断（规则版） | 取最大设备 + 模板句 | 三种数据三种结论都对 | 11 |

**最关键的一步不在网页里**：同一个需求，我先用 Python 手写过一遍（`m2_汇总.py`，60 多行，输出 `报告.txt`）。所以网页版的每个数字我都能**逐位对账** —— 不是"看起来对"，是 `2056.30` 和 `2056.30` 对上。
